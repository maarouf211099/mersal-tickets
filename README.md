# مرسال — نظام التذاكر (v2)

نظام تذاكر داخلي: تيم بيدخّل بيانات الحالة ويحوّلها لتيم الاستقبال، وكل تيم شايف شغله بس،
مع SLA ومسار الهوت لاين دكتور ← الأبحاث ← الفولو اب دكتور.

> **قبل أي حاجة اقرا قسم [ليه النسخة القديمة كانت بتبوّظ السيستمز التانية](#ليه-النسخة-القديمة-كانت-بتبوظ-السيستمز-التانية)** — فيه مشكلة أمنية لازم تتعالج على السيرفر.

---

## طريقة الشغل

### أنواع الحالات والـ SLA
| النوع | الـ SLA | رقم التيكت |
|---|---|---|
| 🚨 طوارئ | 30 دقيقة | `EM-2026-0001` |
| 🆕 نيو كيس | 48 ساعة | `NC-2026-0001` |
| 📋 فولو اب | 72 ساعة | `FU-2026-0001` |

الـ SLA بيتحسب من وقت الإنشاء. لما التيكت تعدّي الموعد، التيم الماسكها + اللي عملها بيوصلهم إشعار مرة واحدة.

### مصدر الحالة
الكول سنتر · السوشيال ميديا · الريسبشن · العيادات.
فيه تيم بنفس الاسم لكل مصدر — لو الموظف في تيم الكول سنتر، المصدر بيتختار لوحده.

### بيانات التيكت
الاسم · موبايل 1 و 2 · الكود · صلة القرابة · الجنسية ·
**مصري ← الرقم القومي (14 رقم)** / **غير مصري ← رقم المفوضية** · تفاصيل · مرفقات (لحد 5 ملفات، 10 ميجا للملف).
الأرقام العربي (٠١٢...) بتتحول لإنجليزي أوتوماتيك.

### التيمات
| التيم | بيظهر كاختيار تحويل لـ |
|---|---|
| تيم إسكندرية | الكل |
| مرسال إيمرجنسي هوت لاين | الكل |
| الريجستريشن / الأوتباوند | الكل |
| هوت لاين دكتور | **مرسال إيمرجنسي هوت لاين بس** |
| الأبحاث / الفولو اب دكتور | بيوصلوا من تصنيف الهوت لاين دكتور |

- **كل تيم مش شايف شغل التيم التاني.** المستخدم بيشوف: التيكتات اللي تيمه ماسكها أو بيتابعها + اللي هو عملها. المدير بيشوف الكل.
- لما مرسال إيمرجنسي هوت لاين يحوّل للهوت لاين دكتور، بيفضل **متابع** (يشوف ويكتب تحديثات، من غير ما يتصرف في التيكت).
- الأسماء والألوان والقيود دي كلها بتتغير من صفحة **التيمات**، وتقدر تضيف تيمات جديدة.

### مسار الهوت لاين دكتور
```
                      ┌─ طارئة ─→ الأبحاث ─┬─ قبول ─→ الفولو اب دكتور
هوت لاين دكتور ───────┤                    └─ رفض (كومنت إجباري) ─→ التيكت تتقفل
                      └─ عاجلة ─→ الفولو اب دكتور + الأبحاث في نفس الوقت
                                   (لو الأبحاث رفضت ← تتقفل بالكومنت)
```

### الحالة والهيستوري
- الحالة: **قيد التنفيذ** أو **مقفولة** (القفل محتاج سبب/ملخص).
- **إعادة الفتح** للمدير أو لأي حد المدير مدّيله صلاحية "إعادة فتح" من صفحة المستخدمين.
- جوه التيكت: **تحديث** أو **ملاحظة** + **منشن** بـ `@اسم_المستخدم` (بيقترح الأسماء وانت بتكتب، والمنشن بيوصل بس للي من حقه يشوف التيكت).
- **الهيستوري الكامل**: الإنشاء، كل تحويل (من مين لمين وليه)، التصنيف، قرار الأبحاث، القفل وإعادة الفتح، الإسناد، أي تعديل في البيانات (القيمة القديمة والجديدة)، والمرفقات.

### الأدوار
| الدور | يقدر |
|---|---|
| مدير | كل حاجة + المستخدمين والتيمات + حذف |
| مشرف / موظف | يعمل تيكتات ويشتغل على تيكتات تيماته (+ مراجعة الموافقات للمشرف) |
| مشاهد | يشوف تيكتات تيماته بس |

صلاحيات إضافية لكل مستخدم: **إعادة فتح** و **تصدير Excel**.
موديول **الموافقات الطبية** من النسخة القديمة متنقل زي ما هو.

## التشغيل على جهازك (للتطوير)

المتطلبات: Node.js 22 و PostgreSQL 14+.

```bash
# 1. داتابيز خاصة بالنظام (مرة واحدة)
psql -U postgres -c "CREATE DATABASE mersal_tickets;"

# 2. الإعدادات
cp .env.example .env        # عدّل DATABASE_URL و AUTH_SECRET و DEFAULT_ADMIN_PASSWORD

# 3. التثبيت والجداول
npm install
npm run db:migrate          # prisma migrate deploy — آمن، ما بيمسحش حاجة

# 4. التشغيل
npm run dev                 # http://localhost:3005
```

ادخل بـ `admin` وكلمة المرور اللي في `DEFAULT_ADMIN_PASSWORD`
(لو سبتها فاضية، كلمة مرور عشوائية بتتطبع في اللوج أول مرة).

لو عدّلت في `prisma/schema.prisma`: `npm run db:migrate:dev -- --name وصف_التعديل` وارفع فولدر الـ migration مع الكود.

## النشر على السيرفر بـ GitHub Actions (self-hosted runner)

كل push على `main`: الـ CI بيتأكد من الـ migrations والـ types والتست والـ build على GitHub،
ولو كله تمام الـ runner اللي على السيرفر بيعمل النشر (`scripts/deploy.mjs`):
migrations ← build ← release جديد ← إعادة تشغيل `mersal-tickets` في pm2 ← health check ← لو فشل يرجع للنسخة اللي قبلها.

### إعداد السيرفر (مرة واحدة)

1. **خلّي الريبو Private.** الـ runner بيشغّل كود على السيرفر؛ والـ workflow مش بيعمل deploy غير من `main`.
2. Node.js 22 + PostgreSQL، وبعدين:
   ```bash
   npm install -g pm2
   ```
   - Linux: `pm2 startup` ونفّذ الأمر اللي بيطلعه (عشان يقوم مع الجهاز).
   - Windows: `npm install -g pm2-windows-startup && pm2-startup install`.
3. اعمل الداتابيز: `CREATE DATABASE mersal_tickets;`
4. اعمل فولدر النشر، مثلاً `C:\mersal-tickets` أو `/opt/mersal-tickets`،
   وحط فيه ملف `.env` (انسخ `.env.example` وعدّله). **الملف ده عمره ما يترفع على GitHub.**
5. سجّل الـ runner: في GitHub ← Settings ← Actions ← Runners ← **New self-hosted runner**
   واتبع الخطوات، وفي خطوة الـ labels اكتب: `mersal-tickets`.
   شغّله كـ service (`./svc.sh install && ./svc.sh start` على Linux، أو اختار "run as service" على Windows)
   **بنفس اليوزر اللي هيشغّل pm2.**
6. في GitHub ← Settings ← Secrets and variables ← Actions ← **Variables**:
   أضف `DEPLOY_DIR` = مسار فولدر النشر (من خطوة 4).
7. اعمل push على `main` (أو Actions ← CI & Deploy ← Run workflow).

الأوامر المفيدة على السيرفر:
```bash
pm2 status                 # الحالة
pm2 logs mersal-tickets    # اللوج
pm2 restart mersal-tickets # إعادة تشغيل النظام ده بس
```

المرفقات بتتحفظ في `DEPLOY_DIR/uploads` — خليها في الباك اب مع الداتابيز.

## ليه النسخة القديمة كانت بتبوّظ السيستمز التانية

1. **🔴 السيرفر غالباً اتخترق — فيه برنامج تعدين عملات (crypto miner).**
   في الملفات اللي اتبعتت كان فيه ملفين مخفيين اسمهم `let` و `let;chmod` — ده برنامج Linux مضغوط (UPX)،
   وجواه أسماء زي `xmrig` و `nanopool` و `c3pool` و `kinsing`. ده نمط معروف لبرامج تعدين بتاكل الـ CPU كله
   **وبتقفل أي عمليات تانية شغالة على الجهاز** — وده لوحده كفاية يبوّظ كل السيستمز.
   النسخة القديمة كانت على `next 15.0.3` + `react 19 RC`، ودي فيها ثغرة معروفة (CVE-2025-55182 / React2Shell)
   بتسمح لأي حد على الإنترنت يشغّل أوامر على السيرفر — والاسم `let;chmod` شكل أمر اتنفذ بالطريقة دي.

   **المطلوب على السيرفر اللي كانت شغالة عليه النسخة القديمة:**
   - افصل النسخة القديمة من الإنترنت ووقّفها.
   - دوّر على عمليات غريبة بتاكل CPU (`top` على Linux / Task Manager على Windows)، وعلى ملفات في `/tmp` و `crontab -l`
     و `~/.ssh/authorized_keys`، والأسماء: `let`, `p.sh`, `alive.sh`, `health.sh`.
   - الأسلم: إعادة تسطيب السيرفر، وتغيير **كل** الباسوردات والمفاتيح اللي كانت عليه
     (باسورد Postgres، `AUTH_SECRET`، أي توكنز في ملفات `.env` للسيستمز التانية).
   - النسخة دي على `next 15.5.28` و `react 19.2.9` (فيهم إصلاح الثغرة دي).
2. **`start.bat` كان بيعمل `taskkill /F /IM node.exe`** — ده بيقفل **كل** برامج Node على الجهاز، يعني أي سيستم تاني شغال بـ Node كان بيقع.
   النسخة دي بتعيد تشغيل عملية pm2 اسمها `mersal-tickets` بس.
3. **`prisma db push --accept-data-loss` مع كل تشغيل** — لو `DATABASE_URL` بيشاور على داتابيز فيها جداول سيستم تاني،
   الأمر ده بيمسحها. النسخة دي: migrations بس، وكل الجداول جوه schema اسمها `tickets` لوحدها.
4. **الكوكيز**: الكوكيز في المتصفح مش بتفرّق بين البورتات، فسيستمين على `localhost` بنفس اسم كوكي الدخول
   بيطلّعوا بعض. النسخة دي اسم الكوكي بتاعها `mersal_tickets_session`.
5. **كلمة سر Postgres** في `.env` القديم فيها `@` من غير encoding — بعض الأدوات بتقرا `DATABASE_URL` غلط بسببها.
   الأسلم تتكتب `%40` بدل `@` (شوف `.env.example`) — وعلى العموم غيّرها بسبب النقطة 1.
6. ملف الأرشيف كان ناقص فيه `middleware.ts` و `sse.ts` (اتقطعوا).
